# MATH 490 Instructor Guide

## Weekly rhythm

> **Prepare → Teach → Practise → Reflect → Apply**

The scheduled class ends at **Wrap-Up**. My Notebook is completed independently after class.

## Instructor Setup

Before class:

1. Select the week.
2. Load or confirm the class dataset when required.
3. Select the target or main outcome.
4. Select starting predictors or variables.
5. Write or generate the class research question.
6. Choose the student freedom level.
7. Enter the practical task and required outputs.
8. Preview the Wrap-Up question prompts.
9. Publish the class brief.

The class research question is instructor-led. The student’s independent assignment question is not generated by the app.

## Today’s Lab

Teach the weekly learning objective, research purpose, essential terms, variable roles, analytical method, and expected outputs. Complete the short readiness check before moving to Practical Studio.

## Practical Studio

The instructor plan loads the initial controls once. It no longer overwrites student selections after every Streamlit rerun.

For Weeks 3 and 4, treat the instructor variables as starting points. Students may freely change:

- Plot type
- Horizontal and vertical variables
- Grouping variable
- Variables used for association
- Other relevant exploratory controls

For later modeling weeks, controls follow the freedom level selected in Instructor Setup.

Require one short practical reflection before students move to Wrap-Up.

## Wrap-Up

Students answer questions one at a time. Regular modules contain 10 questions. Week 8 contains a 50-question midterm review of Weeks 1–7, and Week 16 contains a 50-question final review of Weeks 9–15. Questions assess artificial intelligence and machine-learning concepts, method choice, probability calculations, model behavior, metric interpretation, tuning, regularization, validation, uncertainty, forecasting, computer vision, and common errors. Immediate feedback follows each response. The latest score, best score, and attempt count are saved.

For the review weeks, use the question sequence as the main guided class activity. Pause after difficult questions, ask students to justify each option, and revisit the linked concept before continuing.

## My Notebook

My Notebook is not a submission portal. It is the student’s independent analysis record for preparing the required three-slide presentation.

The student workflow is:

1. Plan the Assignment
2. Run My Analysis
3. Record Findings for Slides

Students must write their own research question. The app does not provide a suggested assignment question.

The final presentation is created and presented outside the app and may be submitted through Canvas.

## Notebook downloads

The readable notebook separates:

- Student independent assignment analysis
- Instructor-led class analysis and practical record

The JSON file is a continuation backup for reopening the notebook in the app.


## Learning Library

Use **Learning Library** whenever a term, model, or parameter needs clarification without interrupting the student's dataset or weekly progress.

The library contains three focused views:

1. **Glossary** — search by word or topic group and display one definition at a time.
2. **Model Explorer** — select a model and teach how it works, what its inputs and outputs are, when to use it, its limitations, and what each parameter controls.
3. **Course Map** — review the progression from Week 1 through Week 16.

A productive classroom rhythm is to introduce a term in Today's Lab, open the matching glossary or model entry briefly, then return to Practical Studio. The library is not an additional assignment unless you choose to make it one.

## Exam Practice

**Exam Practice** is an independent revision area and is not locked behind Practical Studio.

Students may:

- Search a curriculum topic.
- Select foundation, application, and calculation questions.
- Complete 5 to 20 questions one at a time.
- Receive immediate feedback and an explanation after every answer.
- See weak concepts and targeted study advice at the end.
- Download a detailed practice report.

Use focused topic practice before quizzes and use **Full Course Mixed Review** before major examinations. Scores are diagnostic rather than automatically graded. They are stored in the continuation backup and summarized in the readable notebook.

For an online class, ask students to share the downloaded practice report or a screenshot only when evidence of completion is required. The app does not transmit scores to Canvas.

## Teaching rule

Do not display every possible output merely because the app can calculate it. Require only the evidence needed for the current module and its three-slide assignment.

## Visualization behavior

Visualization pages are intentionally blank until the student selects **Show visualization**. Instructor-selected variables may appear as starting values, but the figure is not drawn automatically. Students can change the chart or variables and select the button again to redraw it.

For bar charts, the y-axis states exactly what the bars represent: number of observations, mean of the selected numerical variable, or median of the selected numerical variable.


## Week 13 model-based bootstrap

When students select **Saved model metric** or **Saved individual prediction**, the page now checks for a compatible model. When none is available, students receive a complete model-training panel on the same page. They select the problem type, target, predictors, model, and held-out proportion, then click **Train model for bootstrap**. This prevents the former dead end that only said “Train a model first.”

After every cross-validation or bootstrap run, ask students to read the generated result statements before writing their own interpretation. The statements distinguish estimate, bias, standard error, uncertainty interval, interval width, average validation performance, and stability across resamples.

## Pre-run concept teaching

Each analytical activity now begins with an expanded **Before you run: key terms and metrics** section. Use it to define the method, controls, baselines, and evaluation measures before students click the analysis button. Week 14 additionally detects the typical spacing between time rows and explains how horizon and seasonal-cycle settings translate into future time steps.

## Week 15 image-classification progression

The classroom image activity now supports a deliberate progression from conventional machine learning to image-specialized deep learning:

1. Logistic regression or a support vector machine uses flattened pixel values as a conventional baseline.
2. The feedforward neural network learns nonlinear combinations of the flattened pixels.
3. The small convolutional neural network preserves the image grid and learns local edges, textures, and shapes.

A concise note appears immediately after the classifier is selected. Use this note to discuss how the model reads the image before students train it. The CNN is intentionally small and uses early stopping so it remains appropriate for a classroom dataset and ordinary computing environment.

## Week 15 leakage-aware evaluation

Before training, open **Evaluation audit** with the class. The app follows this order:

1. Preserve a clean predefined `train/val/test` structure.
2. If related sequences or exact duplicates cross the supplied folders, combine the loaded images and create a group-aware holdout.
3. Use a stratified random image-level holdout only when no reliable split or group information exists.

For the supplied ants-versus-bees ZIP, the clean `train` and `val` folders are preserved. For the supplied rock-paper-scissors ZIP, the app detects sequence overlap in the scissors class and rebuilds the holdout so every known sequence stays entirely on one side.

Explain the metric label carefully. **Validation accuracy** is not the same as an untouched final-test score. When a `test` folder exists, CNN early stopping uses a separate validation set and the reported metric uses the test folder.
